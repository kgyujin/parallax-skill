# 프로파일: frontend

UI 컴포넌트 · 화면 · 디자인 시스템. `code` 프로파일과 별개인 이유는
**결함이 "동작하지 않는다"가 아니라 "특정 조건에서 사용자가 막힌다"의 형태로 나타나기** 때문이다.

## 결함의 정의

**특정 뷰포트 · 테마 · 상태 · 입력 방식에서 사용자가 막히거나, 내용을 읽지 못하거나,
의도와 다르게 이해하는 지점.**

디자인 취향은 결함이 아니다. 접근할 수 없는 것이 결함이다.

## 검증 대상 수집

컴포넌트 경로와 함께 **디자인 토큰/테마 정의 위치**를 안내한다.
토큰을 모르면 "하드코딩된 색상"을 잡을 수 없다.

```
컴포넌트:  ./src/components/Dialog.tsx
토큰:     ./src/styles/tokens.css, ./tailwind.config.ts
사용처:   ./src/app/settings/page.tsx
```

## 증거 형식 (필수)

```
조건:   <뷰포트 / 테마 / 상태 / 입력 방식>
경로:   <사용자가 그 상태에 도달하는 방법>
관찰:   <무엇이 보이거나 보이지 않는가>
위치:   <file.tsx:line>
```

"모바일 대응이 부족하다" — 증거 아님.
"375px 뷰포트에서 line 88의 `min-w-[420px]`가 부모를 넘겨, 페이지 전체에 가로 스크롤이 생기고 우측 닫기 버튼이 화면 밖으로 나간다" — 증거.

## 카테고리

| 카테고리 | 내용 |
| --- | --- |
| `a11y_contrast` | 명도 대비가 WCAG AA(본문 4.5:1, 큰 텍스트 3:1) 미만 |
| `a11y_keyboard` | 키보드로 도달·조작·탈출 불가, 포커스 트랩, 포커스 표시 없음 |
| `a11y_semantics` | 역할·레이블·상태가 보조기술에 전달되지 않음 (`aria-*`, 시맨틱 태그) |
| `responsive_break` | 특정 뷰포트에서 레이아웃이 겹치거나, 잘리거나, 가로 스크롤 발생 |
| `state_missing` | 로딩 · 빈 상태 · 에러 · 비활성 · 부분 실패 중 정의되지 않은 것 |
| `theme_break` | 라이트/다크 한쪽에서만 깨짐. 특히 배경 미지정으로 인한 투명 배경 |
| `token_deviation` | 디자인 토큰이 있는데 값을 하드코딩 |
| `inconsistency` | 같은 의미의 요소가 화면마다 다르게 생김/동작함 |
| `hierarchy` | 시각적 강조가 실제 중요도와 어긋나 잘못된 행동을 유도 |
| `motion_a11y` | `prefers-reduced-motion` 미대응, 전정기관 자극 애니메이션 |

## 심각도

- `critical` — 특정 사용자군이 기능을 **아예 사용할 수 없다** (키보드 전용, 스크린리더, 특정 뷰포트).
- `major` — 사용은 되지만 막히거나 잘못 이해한다. 에러 상태 누락, 좁은 화면 레이아웃 붕괴.
- `minor` — 일관성·완성도 문제. 사용은 지장 없다.

## 지적 금지

- 색상 · 폰트 · 여백의 취향 평가
- 디자인 트렌드 논쟁 ("요즘은 이렇게 안 한다")
- 디자이너가 의도적으로 정한 시안과의 차이 (시안이 브리프에 없다면 판단하지 않는다)
- 브라우저 지원 범위 밖 이슈 (범위가 브리프에 없으면 묻고 넘어간다)
- 측정 없는 렌더링 성능 추측

## 브리프 추가 항목

- 지원 대상 뷰포트 범위와 브라우저
- 다크 모드 지원 여부
- 접근성 목표 등급 (WCAG A / AA / AAA)
- 디자인 시안 경로 (있으면)

# 프로파일: writing

블로그 글 · 노트 · 문서 · 발표 원고. 코드도 서류도 아닌 일반 산문.

## 결함의 정의

**독자가 사실이 아닌 것을 사실로 받아들이거나, 논지를 따라가지 못하는 지점.**

글이 밋밋한 것은 결함이 아니다. 틀렸거나 따라갈 수 없는 것이 결함이다.

## 증거 형식 (필수)

```
인용: "<해당 문장 그대로>"
문제: <사실 오류 / 근거 없음 / 앞과 모순 / 논리 비약>
근거: <왜 그렇게 판단하는가, 확인 가능한 출처나 글 안의 다른 부분>
```

"글이 장황하다" — 증거 아님.
"3문단은 'React 19에서 도입된 use() 훅'이라 쓰는데, use()는 React 18.3 canary부터 있었다. 문단 전체가 '19의 신기능'이라는 전제 위에 서 있다" — 증거.

## 카테고리

| 카테고리 | 내용 |
| --- | --- |
| `factual_error` | 검증 가능한 사실이 틀렸다 |
| `unsupported_claim` | 근거 없이 단정한다 |
| `logical_gap` | A에서 B로 넘어가는 근거가 빠졌다 |
| `internal_contradiction` | 글 안의 두 부분이 서로 모순된다 |
| `undefined_term` | 정의 없이 쓰인 용어에 글의 논지가 걸려 있다 |
| `misleading_framing` | 사실은 맞는데 배치·강조가 잘못된 인상을 준다 |
| `broken_reference` | 인용·링크·출처가 실제 내용과 다르거나 존재하지 않는다 |
| `structure_break` | 목차·소제목과 실제 내용이 어긋난다 |
| `ai_tell` | 기계적 병렬, 번역투, 무의미한 수사, 불릿 남발 등 AI 티 |
| `audience_mismatch` | 명시된 독자 수준과 서술 수준이 어긋난다 |

## 심각도

- `critical` — 독자가 사실이 아닌 것을 믿게 된다. 공개된 글에서는 특히.
- `major` — 논지를 따라갈 수 없거나, 핵심 주장에 근거가 없다.
- `minor` — 문체·구조 개선 여지. 이해에는 지장 없다.

## 지적 금지

- 문체 취향, 어휘 선호, 문장 길이 선호
- "더 흥미롭게 쓸 수 있다" 류의 주관 평가
- 글의 주제 선택이나 관점 자체에 대한 반대
- 확인 없는 사실 지적 — `factual_error`는 **무엇이 맞는지** 제시하지 못하면 `confidence: speculative`로 표시한다

## 브리프 추가 항목

- 글의 독자와 목적
- 이미 정해진 논조·입장 (재논의 대상이 아님)
- `ai_tell` 검토 필요 여부 — 필요 없으면 카테고리에서 제외해 노이즈를 줄인다

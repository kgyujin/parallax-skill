# 프로파일: generic

전용 프로파일이 잡히지 않았을 때의 폴백.

**가능하면 이 프로파일을 쓰지 않는다.** 결함의 정의가 흐릿하면 findings도 흐릿해진다.
경로 감지가 실패했을 뿐이라면 사용자에게 프로파일을 물어보는 쪽이 낫다.

## 결함의 정의

**대상이 그 목적을 달성하지 못하게 만드는 지점.**

R0에서 사용자에게 "이 대상의 목적이 무엇인가"를 확인해 이 문장을 구체화한 뒤 진행한다.
목적이 확정되지 않으면 검증을 시작하지 않는다.

## 증거 형식 (필수)

```
위치: <파일:줄 또는 섹션 인용>
주장: <무엇이 잘못됐는가>
근거: <구체적 조건 → 목적 달성 실패>
```

## 카테고리

| 카테고리 | 내용 |
| --- | --- |
| `correctness` | 사실·논리·동작이 틀렸다 |
| `contradiction` | 대상 안에서 서로 모순된다 |
| `omission` | 목적 달성에 필요한 것이 빠졌다 |
| `unsupported` | 근거 없이 단정한다 |
| `unusable` | 형식·접근성·전달 방식 때문에 쓸 수 없다 |

## 심각도

- `critical` — 목적 자체가 달성되지 않는다.
- `major` — 정상 사용에서 문제가 드러난다.
- `minor` — 국소적 · 드문 조건.

## 지적 금지

- 취향 · 선호 · 스타일 평가 전반
- 요청 범위 밖의 재설계 제안

# 프로파일: code

일반 소스코드 변경. 커밋 전 diff, 특정 파일/디렉터리, 브랜치 단위 변경이 대상이다.

## 결함의 정의

**특정 입력·상태·타이밍에서 프로그램이 의도와 다르게 동작하는 지점.**

동작하지 않는 것이 결함이다. 보기 싫은 것은 결함이 아니다.

## 검증 대상 수집

브리프에는 경로와 범위만 준다. 상대가 저장소를 직접 읽게 한다.

```bash
git diff                    # 미커밋 변경
git diff --stat main...HEAD # 브랜치 범위
git log -1 --stat           # 특정 커밋
```

변경 파일뿐 아니라 **호출부와 테스트 경로도 함께 안내**한다. 변경 자체는 멀쩡한데
호출하는 쪽 가정이 깨지는 게 실전에서 더 흔하다.

## 증거 형식 (필수)

```
입력/상태: <구체적인 값 또는 실행 조건>
기대 결과: <무엇이 나와야 하는가>
실제 결과: <무엇이 나오는가>
경로:     <file.ext:line>
```

"경계 조건 처리가 미흡함" — 증거 아님.
"items가 빈 배열일 때 line 42의 `items[0]`이 IndexError를 던진다" — 증거.

## 카테고리

| 카테고리 | 내용 |
| --- | --- |
| `correctness` | 로직이 명세와 다른 결과를 낸다 |
| `regression` | 기존에 동작하던 것이 이 변경으로 깨진다 |
| `boundary` | 빈 값·null·0·최대치·유니코드·음수 등 경계에서 무너진다 |
| `concurrency` | 경쟁 조건, 데드락, 재진입, 순서 의존 |
| `resource_leak` | 파일·커넥션·핸들·구독이 닫히지 않는다 |
| `contract_break` | 공개 API·스키마·이벤트 형식이 호출자 모르게 바뀐다 |
| `error_handling` | 예외를 삼키거나, 실패를 성공으로 보고하거나, 복구 불가 상태로 남는다 |
| `security` | 입력 검증 누락, 인젝션, 경로 이동, 비밀정보 노출 |

## 심각도

- `critical` — 데이터 손상·유실, 보안 취약점, 운영 중단. 되돌리기 어려운 피해.
- `major` — 정상 사용 경로에서 잘못된 결과가 나온다. 사용자가 마주친다.
- `minor` — 드문 경로에서만 발생하거나, 영향이 국소적이다.

## 지적 금지

- 네이밍·포맷·스타일 취향
- 측정 없는 성능 추측 ("이건 느릴 것 같다")
- 아키텍처 재설계 제안 (요청받지 않은 범위)
- 테스트 커버리지 일반론 ("테스트가 더 필요하다") — **어떤 케이스가 왜 필요한지** 짚지 못하면 내지 않는다
- 이미 프로젝트 규약(`AGENTS.md`, 린터 설정)이 허용한 패턴

## 브리프 추가 항목

프로젝트에 `AGENTS.md` / `CLAUDE.md` / `CONTRIBUTING.md`가 있으면 경로를 안내한다.
그 규약이 명시적으로 허용한 것을 결함으로 지적하는 걸 막는다.

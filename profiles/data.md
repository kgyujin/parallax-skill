# 프로파일: data

데이터 분석 · 노트북 · 전처리 파이프라인 · 리포트의 수치.

## 이 프로파일이 존재하는 이유

분석 코드는 **에러 없이 끝나면서 틀린 답을 내놓는다.** 예외가 나지 않으므로
테스트도, 실행 결과도 결함을 알려주지 않는다. 사람이 숫자를 의심해야만 발견된다.

## 결함의 정의

**출력된 수치나 결론이 데이터가 실제로 말하는 것과 다른 지점.**

## 검증 대상 수집

노트북/스크립트와 함께 **데이터의 형태 정보**를 준다. 원본 데이터 자체를 넘기지 않는다
(개인정보·용량). 대신 스키마·행 수·결측률·값 범위를 요약해 브리프에 넣는다.

```
분석 코드:  ./notebooks/churn.ipynb
전처리:    ./src/preprocess.py
데이터 요약: 12,431행 / 컬럼 18개 / signup_date 결측 3.2% / region 값 7종
데이터 출처: 사내 DW snapshot 2026-08-01, 단위=원, 타임존=KST
```

## 증거 형식 (필수)

```
위치:   <셀 번호 또는 file.py:line>
연산:   <문제가 되는 처리>
데이터: <그 처리가 잘못되는 데이터 조건>
결과:   <출력 수치가 어떻게 틀어지는가>
```

"결측치 처리가 미흡하다" — 증거 아님.
"cell 12의 `df.mean()`은 signup_date 결측 3.2%를 자동 제외한다. 그런데 결측은 2026년 이후 가입자에 몰려 있어(cell 8 출력), 평균 체류기간이 실제보다 길게 나온다" — 증거.

## 카테고리

| 카테고리 | 내용 |
| --- | --- |
| `silent_data_loss` | join·필터·dropna가 조용히 행을 날린다 |
| `missing_value_bias` | 결측 처리 방식이 편향을 만든다 (결측이 무작위가 아닐 때) |
| `unit_mismatch` | 단위·통화·타임존·스케일이 섞였다 |
| `aggregation_error` | 잘못된 축·중복 집계·평균의 평균 |
| `leakage` | 학습에 미래 정보나 타깃 파생값이 들어갔다 |
| `wrong_dtype` | 문자열/숫자/날짜 변환이 값을 바꾼다 (선행 0, 반올림, 파싱 실패) |
| `unstated_assumption` | 결론이 명시되지 않은 전제에 기댄다 |
| `overclaim` | 데이터가 지지하는 것보다 강한 결론 (상관을 인과로) |
| `not_reproducible` | 셀 실행 순서 의존, 시드 미고정, 하드코딩된 로컬 경로 |
| `pii_exposure` | 출력·로그·커밋에 개인정보가 남았다 |

## 심각도

- `critical` — 결론이 뒤집힌다. 또는 개인정보가 노출됐다.
- `major` — 수치가 의미 있게 틀렸다. 방향은 맞지만 크기를 신뢰할 수 없다.
- `minor` — 재현성·가독성 문제. 이번 결과는 맞다.

## 지적 금지

- 라이브러리 선택 취향 (pandas vs polars 류)
- 측정 없는 성능 지적 — 분석 코드는 한 번 돌면 끝인 경우가 많다
- 노트북 셀 정리·마크다운 서술 스타일
- 통계 방법론 일반론 — **이 데이터에서 왜 문제인지** 짚지 못하면 내지 않는다

## 브리프 추가 항목

- 이 분석이 답하려는 질문 한 문장 (이게 없으면 `overclaim`을 판정할 수 없다)
- 데이터 출처 · 수집일 · 단위 · 타임존
- 결과가 어디에 쓰이는지 (탐색용인지, 의사결정 근거인지)
